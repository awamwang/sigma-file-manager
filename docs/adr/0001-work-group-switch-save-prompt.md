# Work Group switch uses a save prompt; exit writes back silently

Leaving the Active Work Group to activate another replaces the Navigator Open State, but only after a Switch Save Prompt when that state is dirty: persist into the current Work Group, or into a newly named Work Group (which copies Open State, Member Folders, and group-level settings). Other existing groups are not save targets. After saving or discarding, the originally chosen target Work Group is activated — creating a new group does not retarget the switch. App/window exit does not offer “save as”; it silently writes Open State back to the Active Work Group. Silent autosave on every switch was rejected so users can fork a session without overwriting the group they are leaving; exit stays quiet so quitting is not blocked by naming UI.
