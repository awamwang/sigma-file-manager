# Work Group switch and exit both write Open State back silently

Leaving the Active Work Group to activate another always writes the live Navigator Open State back into the group being left, then restores the target group's Open State—no Switch Save Prompt, discard path, or “save as new group” fork on switch. App/window exit likewise silently flushes Open State to the Active Work Group. A prompt-on-dirty switch was rejected because Open State is session continuity for that group, not a user-facing save decision; forking a session into a new Work Group belongs in explicit create/copy flows, not in every activation.
